# 2026siruba — repo conventions

This is a **hand-authored static site**: one `index.html` (inline `<style>` +
~110-line inline `<script>`, no framework, no bundler), a Python script
(`build_artifact.py`, Pillow only) that inlines `images/*.jpg` as base64 data
URIs for a single-file distributable, and nothing else. No package.json, no
CI, no test suite. Don't apply React/Tailwind/npm-project assumptions here —
there is no build pipeline beyond that one script.

## Verification commands (run these, not "looks right")

```sh
# 1. Every region's budget must reconcile across FOUR places at once:
#    table row sum == table <tfoot> == card__foot "2日間合計" == HERO.budget in <script>
python3 - <<'PY'
import re
s = open('index.html').read()
for rid in re.findall(r'id="region-(\w+)" class="region"', s):
    m = re.search(rf'<div id="region-{rid}" class="region"[^>]*>(.*?)<!-- /region-{rid} -->', s, re.S)
    blk = m.group(1)
    tb = re.search(r'<tbody>(.*?)</tbody>', blk, re.S)
    if not tb: continue  # ibaraki nests its budget inside panel-budget, check separately
    vals = [int(v.replace(',','')) for v in re.findall(r'class="n">¥([\d,]+)</td>', tb.group(1))]
    foot = re.search(r'<tfoot>.*?¥([\d,]+)', blk, re.S)
    cardfoot = re.search(r'2日間 合計</span>\s*<span class="sum">¥([\d,]+)', blk)
    hero = re.search(rf'{rid}:.*?budget: "¥([\d,]+)"', s, re.S)
    # ibaraki is the 5-day full itinerary and has no "2日間合計" card footer —
    # that label only exists on the four 2-day alternates. Guard for None.
    nums = [foot.group(1), hero.group(1)] + ([cardfoot.group(1)] if cardfoot else [])
    ok = sum(vals) == int(foot.group(1).replace(',','')) and len(set(nums)) == 1
    print(rid, sum(vals), foot.group(1), cardfoot.group(1) if cardfoot else '(no card footer: ibaraki)',
          hero.group(1), 'OK' if ok else '*** MISMATCH ***')
PY

# 2. Every images/xxx.jpg referenced must exist, and every file in images/ must be referenced
#    (orphans silently bloat the repo and the single-file build)
grep -o 'images/[a-z-]*\.jpg' index.html | sort -u | while read f; do [ -f "$f" ] || echo "MISSING $f"; done
for f in images/*.jpg; do grep -q "$f" index.html || echo "UNUSED $f"; done

# 3. Tag balance (catches a stray unclosed div from a batch edit)
python3 -c "
import re; s=open('index.html').read()
print('div', len(re.findall(r'<div\b', s)), len(re.findall(r'</div>', s)))
print('section', len(re.findall(r'<section\b', s)), len(re.findall(r'</section>', s)))
print('table', len(re.findall(r'<table\b', s)), len(re.findall(r'</table>', s)))
"

# 4. Rebuild the distributable and confirm zero unembedded image paths remain
python3 build_artifact.py
grep -c '"images/' dist/silver-week-2026.html   # must print 0

# 5. Render every region tab in a real browser and check for console errors / horizontal overflow
#    (see "Runtime check" pattern below — this is not optional, JS bugs here are silent)
```

## Forbidden, and why

- **Don't add a color as a literal hex/rgb outside the `:root` custom-property
  tokens** (`--moss`, `--ryujin`, `--kuri`, `--stone`, etc.). Every token is
  redefined three times (bare `:root`, `@media prefers-color-scheme: dark`,
  `[data-theme="dark"]`) — a literal color skips all three and silently
  breaks in dark mode only, which you won't notice testing in light mode.
- **Don't link a webfont or any external asset.** This file is designed to
  also work as a Claude Artifact (strict CSP, no external hosts except Google
  Fonts, which we don't use either) and as an emailed single file. System
  font stacks only.
- **Don't hand-edit `dist/`.** It's gitignored and fully regenerated by
  `build_artifact.py` from `index.html`. Any fix belongs in `index.html`.
- **Don't state a total (¥ amount) in only one place.** Every region's
  headline number appears in 4 places (see verification command 1). Editing
  one and not the others is the single most common bug in this repo's
  history — it has happened twice.
- **Don't assume `build_artifact.py`'s regex catches new patterns for free.**
  It replaces `"images/…"` — any quoted string, HTML attribute or JS string
  literal alike. If you introduce a *new* way to reference an image (e.g. a
  template literal, an unquoted attribute, a CSS `url(images/…)`), it will
  NOT be caught and the single-file build will silently 404 that image only
  in the distributed version, not in the source-served version. Test the
  actual `dist/` output, not just `index.html`.

## Adding a new destination/region: touch files in this order

1. **Source real photos first**, from Wikimedia Commons (`commons.wikimedia.org`
   API `list=search`), check the license (`CC BY`/`CC BY-SA`/public domain
   only), download via the API's `thumburl` (originals 429-rate-limit
   aggressively; thumbnails don't), and **open every photo and look at it**
   — season, subject, and framing described in a search result title have
   been wrong before (a "garden" photo that was actually a night market, a
   "waterfall" photo that was frozen solid when the trip is in September).
   Downscale to ≤1280px wide, JPEG quality ~72-78, keep each file under
   ~300KB.
2. Add the region's `<div id="region-{id}" class="region" hidden>` block to
   `index.html`: intro `.flag`, `.minidays` with `.card` day-blocks (reuse
   the component classes below), a `.budget` table.
3. Add the matching `region-tab-{id}` button in `.regionbar`.
4. Add a `{id}: {...}` entry to the `HERO` object in the `<script>` block —
   **all six fields** (`img`, `alt`, `title`, `note`, `days`, `budget`,
   `credit`). A missing field doesn't error, it just leaves stale text from
   the previously-selected region on screen — silent, easy to miss.
5. Run verification command 1 (budget reconciliation) before moving on.
6. Add photo credits to the footer `.credits` block and a source link to
   `.sources`, in the same "name — CC BY-SA X.X" format as existing entries.
7. Rebuild `dist/` (verification command 4) and do a real Playwright render
   of the new region (screenshot + console-error check) before considering
   it done.
8. Update `README.md`'s summary table/bullet list if the change affects the
   top-level pitch (budget, region count, transport mode).

## Reusable components (don't reinvent)

- Day card: `.card > .card__media img + .card__cap` (photo+caption) then
  `.card__body > .card__title (h3 + .theme-tag) + .card__lede + .sched dl +
  .card__foot` (subtotal). Used identically in the 5-day Ibaraki itinerary
  and the four 2-day alternates.
- `.flag` — a note box, left border colored `var(--ryujin)`. Variant
  `.flag--car` (border `var(--kuri)`, background `var(--surface-sunk)`,
  optional `table.mini` inside) for cost-comparison call-outs.
- `.budget` table — `<caption>` states the assumptions, `<tfoot>` states the
  total. Row order convention: 交通 → 宿 → 食事 → 入場/現地移動 → 予備.
- Two independent tab systems share one `wireTabs(selector)` JS function:
  `.region-tab` (outer, 5 destinations) and `.tab` (inner, Ibaraki-only:
  旅程/予算/差し替え/準備). Don't write a third bespoke tab implementation —
  extend `wireTabs`.

## Known pitfalls (things that have actually gone wrong here)

- **Region-scoped find/replace by loose regex can hit the wrong region.**
  Two regions can contain the byte-identical string (e.g. two different
  regions both showing `¥40,000<small>2人分</small>` before a price
  correction). A regex anchored only by a preceding HTML comment, without
  first verifying the comment-to-div adjacency actually holds, has silently
  patched the wrong region's card footer while reporting success. Always
  re-verify with an independent read (grep the specific line) after a
  scripted edit that targets "one of several identical-looking blocks."
- **README claims can drift from the code.** The README currently says
  "JavaScriptなし" (no JavaScript) — false, there's a ~110-line inline
  script. Don't trust the README's own description of the codebase when
  auditing; check the file.
- **A schedule line item's yen amount and the budget table row must be
  updated together.** Adding/changing a `<span class="yen">` in a `.sched`
  `<dd>` without re-summing the corresponding `.budget` table row is how a
  ¥3,000 lunch once went missing from a stated total.
